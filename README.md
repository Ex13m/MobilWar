# MobilWar

Локационный AR-шутер для небольшой группы на ограниченной территории (школьный двор, парк). Веб-приложение (PWA) — без установки из сторов. Каждый игрок — 3D-аватар, которого видят все остальные в AR по его реальной GPS-позиции. Мировая сеть «зон» с локальными боями. Два способа играть:

- **AR-режим** — камера + 3D-наложение, целишься телефоном, тап — выстрел.
- **Режим без экрана («сталкер»)** — телефон в руке направлен вперёд, звуковой радар (стерео-пинг: чаще и выше — ближе, слева/справа — направление), голосовые подсказки, попадание по GPS-координатам + компасу.

Можно ставить AR-объекты по GPS-координатам: **турели** (автоматически стреляют по врагам в радиусе), укрытия, аптечки. Режимы: командный бой, захват флага, царь горы, заражение, оборона турелей. Отдельная страница **судьи** (учитель/взрослый) с живой картой, геозоной и кнопками старт/стоп/кик.

## Структура

```
packages/shared   гео-математика (ENU, haversine), протокол WS, конус попадания с моделью GPS-ошибки,
                  фильтры позиции/курса, античит (правдоподобие скорости), token bucket
apps/server       Node 22 + ws. Авторитарная симуляция 10 Гц: комнаты-зоны, турели, режимы,
                  геозона, судья, SQLite (better-sqlite3), HTTP /health /api/rooms /api/leaderboard
apps/client       Vite + TypeScript + three.js. Лобби, AR-lite (видео камеры + DeviceOrientation, iOS),
                  WebXR immersive-ar (Android Chrome, dom-overlay), режим без экрана (Web Audio HRTF радар,
                  TTS, вибрация), HUD с мини-радаром, страница судьи (Leaflet)
```

## Быстрый старт (локальная сеть, одна школа)

Требования: Node ≥ 22, pnpm 10.

```bash
pnpm install
pnpm dev              # сервер ws://<ip>:8080, клиент https://<ip>:5173 (самоподписанный сертификат)
```

1. Ноутбук и телефоны в одной Wi-Fi сети.
2. На телефоне открыть `https://<ip-ноутбука>:5173`, принять предупреждение о сертификате (нужен HTTPS для камеры/GPS/компаса).
3. Первый игрок нажимает «Создать зону» (центр — где он стоит), получает 4-значный код.
4. Остальные вводят код или выбирают зону из списка «рядом».
5. Судья открывает `https://<ip>:5173/referee.html?room=КОД` на планшете и нажимает «Старт».

Клиент берёт адрес бэкенда из `VITE_API_URL` (см. `apps/client/.env.example`); по умолчанию в dev — `<хост-страницы>:8080`, в проде — тот же origin. Лобби ходит по HTTP (`/api/rooms`), игра — по WebSocket `/ws/<КОД>`.

## Деплой

Три варианта:

| Вариант | Что нужно | Публичный доступ | Стоимость |
|---|---|---|---|
| **Cloudflare Workers через Higgsfield** (`deploy/higgsfield/`) | ничего, уже развёрнуто: https://mobilwar.higgsfield.app | нет: платформа требует вход в Higgsfield-аккаунт на каждом устройстве | 0 |
| **Render** (`render.yaml`) | подключить GitHub-репо в Render → Blueprint | да | free (сервер засыпает) / ~7 $ |
| **Свой VPS** (`docker-compose.yml`) | любой Linux с Docker + домен с HTTPS | да | от 3–5 $ |


- **Сервер**: `apps/server/Dockerfile` (образ ~150 МБ, том `/data` для SQLite). `docker compose up` для локального запуска. `render.yaml` — blueprint для Render (сервер + статика). Переменные: `PORT`, `DB_PATH`, `ALLOWED_ORIGINS`, `REFEREE_PIN`.
- **Клиент**: статика из `apps/client/dist` на любой CDN (Cloudflare Pages / Netlify / Render Static). Обязателен HTTPS.

## Как это работает (коротко)

- Координаты игроков переводятся в локальную плоскость ENU относительно центра зоны (метры). Север = −Z в three.js.
- Клиент шлёт `pos` 4 Гц (lat/lon/accuracy/heading). Сервер отбрасывает неправдоподобные прыжки (скорость > 9 м/с с учётом бюджета GPS-ошибки) и точность хуже 40 м.
- Выстрел = курс компаса. Сервер ищет цель в конусе: полуугол `max(10°, atan(R/d))`, где `R = 3 м + ½(точность стрелка + точность цели)` — чем ближе и чем хуже GPS, тем шире конус. Урон падает после 60 % дальности.
- Турели — серверный цикл: ближайший враг в радиусе 25 м, выстрел раз в 1.5 с.
- Снапшоты 10 Гц; клиент интерполирует чужие позиции с задержкой 250 мс, свою — фильтром с весом по точности.
- В режиме без экрана клиент считает относительный пеленг до ближайшего врага и играет пинг через `PannerNode` (HRTF); при захвате в конус — короткий сигнал, тап/встряхивание — выстрел.

## Ограничения MVP-1

- iOS Safari не поддерживает WebXR — используется AR-lite (видео + гироскоп/компас), объекты не «приклеены» к поверхности, точность позиции = GPS (3–10 м на открытой местности).
- Вибрации на iPhone нет (нет Vibration API) — только звук.
- Кнопки громкости веб-странице недоступны — выстрел тапом или встряхиванием.
- Без аккаунтов: профиль по `deviceId` в localStorage.
